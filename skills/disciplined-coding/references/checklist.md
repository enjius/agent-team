# 완료 전 자기점검 (Disciplined Coding)

코드를 "완료"로 보고하기 직전, 아래를 스스로 통과시킨다. 하나라도 ✗면 완료가 아니다.

## 착수 전 (Think)
- [ ] 바꿀 대상 주변 코드를 읽고 기존 패턴·관례를 파악했다.
- [ ] "무엇을·왜" 바꾸는지 한 줄로 말할 수 있다.
- [ ] 불확실한 점은 추측이 아니라 확인/질문으로 해소했다.

## 변경 중 (Simple + Surgical)
- [ ] 가장 적게 바꾸는 해법이다. 추측성 추상화·미래 대비 코드가 없다.
- [ ] 기존 스타일·네이밍을 따랐다. 새 패턴/라이브러리를 임의 도입하지 않았다.
- [ ] diff가 목표 범위 안이다. 무관한 파일·리팩터·재포맷이 섞이지 않았다.
- [ ] 요청되지 않은 기능·옵션을 추가하지 않았다.

## 완료 전 (Goal + 증거)
- [ ] 변경이 목표/수용조건(AC)에 직접 연결된다. 범위 이탈이 없다.
- [ ] 결함 수정이면 실패하는 테스트를 먼저 썼고, 이제 통과한다.
- [ ] 엣지케이스·널·에러 경로를 처리했다.
- [ ] **실제로 빌드/실행/테스트를 돌려** 목표 충족을 확인했다(증거 있음).
- [ ] TODO/스텁/`test.skip`/미구현 분기가 없다. 있으면 블로커로 보고했다.

> 하나라도 못 채우면 "완료"라고 말하지 말고, 미충족 항목을 블로커로 명시한다.
