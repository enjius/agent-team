# Disciplined Coding — AI 코딩 규율 (Superpowers + Karpathy 4원칙)

목적: "반응형 코드 생성기"가 아니라 **시니어 개발자처럼** 행동하게 만든다.
코드를 한 줄이라도 쓰기 전에 이 규율을 적용한다.

## Karpathy 4원칙 (강제)

### 1. 코딩 전 사고 (Think Before Coding)
- 코드를 쓰기 전에 문제를 이해하고 **주변 코드를 먼저 읽는다** — 관례·의존성·기존 패턴 파악.
- "무엇을·왜 바꾸는가"를 한 줄로 말한 뒤 착수한다. 불확실하면 추측하지 말고 확인·질문.
- 첫 아이디어를 반사적으로 타이핑하지 않는다.

### 2. 단순함 우선 (Simplicity First)
- **가장 적게 바꾸는 해법**을 고른다. 추측성 추상화·미래 대비 일반화 금지(YAGNI).
- 기존 코드의 스타일·네이밍·관용을 따른다. 새 패턴·새 라이브러리를 함부로 도입하지 않는다.
- 요청되지 않은 기능·옵션·설정을 덧붙이지 않는다.

### 3. 수술적 변경 (Surgical Changes)
- **필요한 곳만** 건드린다. diff를 작게 유지. 무관한 코드 리팩터·재포맷 금지.
- 동작을 보존한다. 바꾸는 것은 목표에 필요한 것만.
- 대규모 재작성(sweeping rewrite)은 명시적 요청·승인 없이는 하지 않는다.

### 4. 목표 주도 실행 (Goal-Driven Execution)
- 모든 변경을 실제 목표/수용조건(AC)에 연결한다. 목표에서 벗어나는 걸 발견하면 **멈추고 보고**.
- 완료 전 목표가 **실제로** 충족됐는지 확인(빌드/실행/테스트). 범위 이탈(scope creep) 금지.

## 시니어 개발자 행동 (Superpowers)
- 결함엔 **실패하는 테스트를 먼저** 쓴다(TDD) → 통과시키는 최소 변경 → 리팩터.
- **추정보다 증거.** "될 것"이 아니라 실제로 돌려보고 완료를 보고한다.
- 엣지케이스·널·에러 경로를 먼저 생각한다. 해피패스만 짜지 않는다.

## 절대 하지 말 것 (AI 코딩 함정)
- TODO/placeholder 스텁, `test.skip`/`.only`, 미구현 분기를 "완료"로 보고 → **블로커다.**
- 요청 안 한 기능 추가, 무관한 파일 대량 수정, 조용한 범위 확장.
- 테스트·빌드 없이 "됐다"고 단정.

## 우리 팀 흐름과의 연결
- `/build` 파이프라인의 **구현 단계**(flutter-builder·backend-dev·supabase-backend 등)에서 이 규율을 적용한다.
- 그 뒤 **code-reviewer·flutter-code-reviewer·verifier 게이트**가 이 규율 준수를 검증한다
  (수술적 변경인가·스텁 없는가·목표 충족했는가).
- 완료 보고 전 `references/checklist.md`의 자기점검을 통과할 것.

상세 자기점검: `references/checklist.md`.
