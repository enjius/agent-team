# Wayfinder — 멀티세션 계획을 '결정 지도'로 밖에 주차한다

핵심 아이디어(Matt Pocock의 wayfinder에서): **큰 계획을 컨텍스트 창에 이고 다니지 않는다.**
결정해야 할 것들을 **티켓 지도**로 세션 밖에 저장하고, 하나씩 해소하며 목적지까지 길이 뚜렷해질 때까지 반복한다.
컨텍스트 파일이 지식을 세션 '안으로' 나른다면, wayfinder는 결정을 세션 '밖으로' 나른다.

## 언제 쓰나
- 한 세션/한 에이전트가 다 못 쥐는 작업(대형 기능, 마이그레이션, 리아키텍처, 신규 도메인).
- `/plan`(단일 세션 PRD)·`/council`(단건 결정)로는 부족한, **여러 결정이 얽힌 장기 작업**.

## 지도를 어디에 주차하나 (우선순위)
1. **이슈 트래커**(권장, 있으면): `gh issue` 로 각 결정을 티켓으로. 라벨 `wayfinder`, 블로킹 관계는 이슈 본문에 `blocked-by #12`.
2. **폴백(트래커 없음)**: `knowledge/<project>/wayfinder.md` 에 아래 형식으로. 어느 세션이든 이 파일을 읽어 이어간다.

## 절차
1. **목적지 한 줄**: "이 작업이 끝나면 무엇이 참인가"를 명확히 적는다.
2. **결정 티켓으로 분해**: 남은 것을 '작업'이 아니라 **결정(open question)** 단위로 쪼갠다.
   각 티켓 = 제목 / 왜 결정이 필요한가 / 선택지 / 블로킹(무엇이 먼저 정해져야) / 상태(open·resolved).
3. **블로킹 순서로 하나씩 해소**: 블로킹 없는 티켓부터. 결정이 서면 **이유와 함께** resolved 처리하고
   `knowledge/<project>/decisions.md`에도 남긴다(→ `/council`을 티켓 해소에 써도 됨).
4. **지도 갱신**: 결정이 새 결정을 낳으면 티켓을 추가한다. 컨텍스트가 아니라 지도가 진실의 원천.
5. **길이 뚜렷해지면**: 모든 결정 티켓이 resolved → 이제 실행 단계. `/build`(구현)로 넘긴다.

## 세션 재개
새 세션은 컨텍스트를 복원하지 않는다 — **트래커/`wayfinder.md`의 open 티켓만 읽고** 이어서 해소한다.
이게 wayfinder의 요점: 세션이 끊겨도 계획이 살아남는다.

## 형식 (wayfinder.md)
```markdown
# Wayfinder — <작업명>
목적지: <끝나면 참이 되는 한 줄>

## T1. <결정 제목>  [open|resolved]
- 왜: <이 결정이 필요한 이유>
- 선택지: A) … B) …
- blocked-by: (없음 | T0)
- 결정: <resolved면 무엇을·왜. open이면 비움>
```

담당: 총괄(tech-lead/orchestrator)이 지도를 관리하고, 각 티켓 해소는 관련 리더/`/council`에 위임.
