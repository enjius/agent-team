# knowledge/ — 팀 지식 베이스

에이전트는 매 세션 백지에서 시작한다. 여기는 세션을 넘어 쌓이는 지식이 사는 곳이다 —
태스크 그래프(팀·커맨드)가 "일하는 방식"이라면, 이 폴더는 "기억하는 방식"이다.

## 구조

```
knowledge/
  README.md              ← 이 파일 (규칙)
  <프로젝트명>/
    decisions.md         ← 내린 결정 + 이유 (가장 중요)
    domain.md            ← 도메인 사실 (규제·용어·제약)
    glossary.md          ← 프로젝트 고유 용어 (선택)
```

## 규칙

- **결정은 이유와 함께.** "무엇을 골랐나"만 적으면 나중에 같은 논쟁을 반복한다.
  형식: `## 결정 제목` / `날짜` / `결정` / `이유` / `대안과 기각 사유`.
- **날짜는 절대 날짜로** (예: 2026-08-08). "지난주" 같은 상대 표현 금지.
- **코드에서 알 수 있는 건 적지 않는다.** 코드 구조·과거 수정 내역은 git이 기억한다.
  여기엔 코드만 봐서는 알 수 없는 것만: 왜 그렇게 했는지, 외부 제약, 도메인 지식.
- **에이전트 사용법**: 팀에 작업을 시킬 때 관련 프로젝트의 `decisions.md`·`domain.md`를
  컨텍스트로 먼저 읽힌다. 작업 중 새 결정이 나오면 해당 파일에 추가한다.
